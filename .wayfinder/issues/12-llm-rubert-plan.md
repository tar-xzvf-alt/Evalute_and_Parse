### 2. Результат LLM — одна публикация

- Включить/исключить по предмету и региональной привязке.
- Причина исключения, территориальная категория и основание привязки — контроль происхождения решения.
- Для включённых: одна оценка (положительная/отрицательная/смешанная/без определённой оценки) и несколько из восьми тем.
- Короткое основание для просмотра человеком.
- Для исключённых оценка отсутствует и список тем пустой. Отдельные события, состояния, стадии, характер сообщения не предсказываются.

Смешанная — существенные положительная и отрицательная стороны в самом тексте; отсутствие определённой оценки — нехватка оснований для знака, не нерелевантность. Фон решаемой проблемы не создаёт смешанность сам по себе. План не считается реализованным фактом, хотя отдельно не кодируется.

### 3. RuBERT A — фильтр

Вход: текст и регион источника. Выход: включить/исключить, объединяя предметную и территориальную пригодность. Причины исключения сохраняются для контроля, но на первом этапе не выделяются в отдельную обучаемую задачу. Метаданные региона нужны, поскольку часть привязок по согласованной инструкции определяется по источнику. Точное кодирование региона пока не выбрано; ID конкретного паблика не должен молча подменять содержание.

### 4. RuBERT B — оценка и темы

Применяется к прошедшим фильтр публикациям. Общая предобученная русскоязычная BERT-основа с двумя выходами: четырёхклассовая оценка и восемь независимых тематических меток. Несколько тем допустимы. Объяснения LLM не являются обязательной генеративной задачей RuBERT.

Дообучение, не обучение с нуля. Конкретный checkpoint, доступная GPU/VRAM, длина входа и обработка длинных текстов, размеры разбиений, class weights, параметры обучения и пороги тематических выходов ещё требуют выбора. Существующая SDG-модель не является готовым классификатором этой задачи.

### Среды работы: ноутбук и Windows-ПК

Пользователь уточнил: **на рабочем ноутбуке нет видеокарты NVIDIA; обе модели RuBERT обучаются на его отдельном ПК под Windows**. На ноутбуке остаются сбор VK, LLM-разметка через OpenCode, проверка/подготовка данных и формирование переносимого набора. Обучение на ноутбуке не планируется и не запускается; установка CUDA/PyTorch для него сейчас не требуется.

До подготовки окружения обучения на Windows-ПК отдельно установить точную модель GPU, объём VRAM, версии Windows/драйвера и подходящую связку Python/PyTorch. Ранее обсуждавшаяся NVIDIA 1660 не является подтверждённой конфигурацией ПК. Наличие NVIDIA/CUDA на целевом ПК не считается проверенным по факту Windows. Не переносить Linux venv на Windows: создать отдельное окружение с зафиксированными зависимостями.

Для переноса подготовить датасеты/метки, групповые разбиения, словари меток и версию инструкции, параметры/seed, манифест и SHA-256, затем код обучения. Пути сделать относительными или конфигурируемыми; секреты VK/OAuth в пакет не включать. Модельные checkpoint и журналы обучения сохранять отдельно с конфигурацией. Передача корпуса — локальная, без автоматической публикации в Git. Работоспособность CUDA и обучения проверяется на ПК, а не объявляется по Linux-тестам сборщика.

### 5. Проверка и разделение данных

Основная разметка машинная, человек просматривает готовые ответы и отмечает спорные случаи в посильных партиях. Просмотр включает как принятые, так и отвергнутые тексты. Исходные ответы, подтверждения и исправления сохраняются отдельно; принятие не предполагается по молчанию.

Обучение/настройка/отложенная проверка разделяются до обучения с группировкой одинаковых и близких текстов, без утечки копий. Размеры и состав ещё не утверждены. Отложенность текстов не устраняет влияние показанных машинных ответов на человеческие метки. Метрики на машинной/ассистированной разметке описывают совпадение с ней, не независимую семантическую истинность. Прежняя обязательная слепая разметка 60/100 отменена как обязательство пользователя. Один принятый смешанный пример не доказывает достаточности класса.

### 6. Применение и исследовательская цель

После отдельно разрешённого сбора и контроля пригодности RuBERT обрабатывает 2020–2024 годы, 28 фиксированных источников 14 субъектов ПФО: фильтр → оценка/темы. LLM не обязана размечать весь исследовательский период. Годовые агрегаты по источникам с равными весами источников в регионе сопоставляются с безработицей, индексами реальной зарплаты и физического объёма розницы. Проверяется добавочная информация оценок сверх объёма и тем; причинность/прогноз не обещаются. Конкретные публикационные знаменатели, основной оценочный предиктор и статистический вывод открыты в вопросах 06/10/11.

## Разрешённый тест расхода на 1000 текстах

Пользователь отдельно разрешил тестовую LLM-разметку 1000 текстов и учёт токенов/пятичасовой квоты. Используются уже собранные тексты Омска-2019, поскольку новые ПФО-2019 тексты не собраны. Это ограниченная техническая задача, не обучение и не разрешение основного сбора/разметки всего объёма.

Отбор: непустые уникальные нормализованные тексты, без прежней выборки разработки 200 и её точных нормализованных повторов; по 500 из двух источников, фиксированный seed. Это сбалансированная выборка для замера расхода, не оценка распространённости классов. Пакеты максимум по 25 текстов, с ограничением суммарного объёма без усечения отдельных текстов; последовательные запросы, без автоматических повторов runner. Ошибка доступа, таймаут или лимит останавливают выполнение. Невалидный ответ не выдаётся за завершённую разметку; фактические отправленные/полученные объёмы раскрываются.

Токены и сырые ответы сохраняются по запросам. API OpenCode /api/experimental/usage/limits по документации измеряет Console/Go, не ChatGPT Plus, и возвращает null. Процент пятичасовой квоты нельзя выводить из токенов; при отсутствии надёжных снимков провайдера до/после он остаётся неизвестным. Ручное сравнение счётчиков также может включать другую активность аккаунта и сброс окна. Секреты OAuth не извлекаются.
