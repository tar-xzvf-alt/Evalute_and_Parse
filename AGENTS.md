# Инструкции для работы с ParseVK

## Назначение и границы

Проект собирает региональные публикации VK, выполняет словарный анализ тональности и содержит отдельные скрипты SDG-классификации и статистического анализа. Новый сборщик доступен через GUI и CLI. Будущая LLM-разметка, обучение модели оценки событий и единый анализ связей с Росстатом ещё не являются готовыми функциями приложения.

Пользовательские инструкции начинаются с `README.md`. Перед изменением:

- **Сбора, профилей, форматов и границ года** — читать `docs/vk-collection.md`.
- **CLI и автоматизации** — читать `docs/cli.md`.
- **Установки, шрифтов и запуска на другой платформе** — читать `docs/getting-started.md`.
- **Словарей, SDG-модели и старых аналитических скриптов** — читать `docs/analysis.md`.
- **Проверки живого корпуса** — читать `docs/pilot-checklist.md`.

## Окружения и проверки

- GUI Linux: `bash scripts/setup_gui_env.sh`, затем `bash run_gui.sh`. Зависимости — `requirements-gui.txt`, окружение — `.venv-gui`.
- CLI без графической среды: `python -m parsevk`; минимальные зависимости — `requirements-cli.txt`. Запуск модуля из корня репозитория, из другого каталога — по абсолютному пути к `parsevk.py`.
- TensorFlow SDG: отдельный Python 3.10 с `requirements02022026.txt`. Современное окружение GUI не заменяет это окружение.
- Тесты: `.venv-gui/bin/python -m unittest discover -s tests -v`. Без DISPLAY тест окна пропускается, остальные должны работать. В тестах используется подменный VK-клиент; реальные запросы и ключи в них не добавлять.
- Системы сборки, общего линтера и проверки типов пока нет. Успешные тесты сборщика не подтверждают работоспособность всех старых аналитических скриптов.

В проверенном старом `myenv` Tk собран с `fontsystem=x11`, что даёт пиксельные шрифты. Системный Tk/Xft решает сглаживание; замена семейства не исправляет отсутствие Xft. Оформление централизовано в `src/ui_theme.py`, фигуры рисуются без специального шрифта CustomTkinter. Отображение Windows отдельно не подтверждено.

## Архитектура сбора

- `src/vk_collection.py` — клиент API, поиск границ периода, выгрузка, профили и паспорт запуска; без Tk.
- `src/collection_workflow.py` — общая проверка параметров, оценка активности и автоотбор GUI/CLI. Изменять правила здесь, а не дублировать во фронтендах.
- `src/collection_cli.py` — аргументы команд, JSON-вывод, коды завершения и сигналы; `parsevk.py` — точка входа. CLI не должен импортировать Tk, CustomTkinter, NLTK или TensorFlow.
- `src/collection_ui.py` — новый экран; фоновые задачи передают сообщения в очередь, обновление Tk — в главном потоке.
- `src/TryToParse_new.py` — общее окно, старые вкладки анализа и сбора комментариев.
- `src/parsar.py` — совместимость старого сбора; посты получает через новый поиск периода.

Периоды нового сборщика — полуоткрытые UTC-интервалы. Закреплённые записи обрабатываются отдельно. При росте стены допускается до трёх восстановлений по подтверждённым опорным страницам; неподтверждённые изменения остаются ошибкой. API не предоставляет снимок стены. Ошибку источника отличать от нуля публикаций. Повторный запуск профиля сохраняет выбранный набор; переподбор требует явной команды. Режим `--resume`/«Продолжить…» переиспользует завершённые источники после локальной сверки файлов; это не дописывание частичного JSONL.

Форматы результатов и ограничения описаны в `docs/vk-collection.md`; не считать новые имена файлов автоматически совместимыми со старыми агрегаторами. Источником идентичности публикации является пара `(group_id, post_id)`.

## Секреты и данные

- `vk_token.txt` игнорируется Git. CLI также принимает `VK_TOKEN` или путь через `--token-file`. Сам токен не передавать аргументом и не включать в вывод, профили, паспорта, тестовые фикстуры или коммиты.
- Старый ключ был опубликован в истории Git; удаление из текущего кода не очищает историю и не делает ключ безопасным.
- Корпуса и локальные отчёты сохранять в игнорируемом `data/raw/`. Не добавлять выгрузки в Git автоматически. Фактические правила исключения смотреть в `.gitignore`: не все Excel-файлы во всех каталогах исключаются одним глобальным правилом.
- Словари `data/kartaslovsent.csv` и `data/rusentilex.csv` — зависимости приложения. У первого разделитель `;` и дробные значения, у второго — `,` и значения -1/0/1. При перемещении обновить потребителей.
- `data/region_stats/region_indicators.csv` — сохранённые региональные показатели, не новый автоматически обновляемый сервис Росстата.

## Совместимость старого кода

Несколько модулей используют `resource_path()` и `sys._MEIPASS` для PyInstaller. Сохранять работу ресурсов в разработке и учитывать упаковку; изменения GUI не означают проверенную сборку Windows `.exe`.

`rubert_bert_RU_35data_6_epochs/` — внешняя TensorFlow SavedModel, не формат HuggingFace; загрузчик в `src/evaluate_script.py` пробует два метода и базу `DeepPavlov/rubert-base-cased`. Это модель ЦУР, не тональности экономических событий.

`src/analyse.py` требует внешние `combcombcomb.xlsx` и `comb_test_1.xlsx`. Несколько других старых скриптов имеют жёстко заданные пути; проверять их перед запуском, не представлять как готовый единый CLI.

## Состав репозитория

Здесь сохраняются код, тесты, словари, необходимые данные и эксплуатационная документация. LaTeX-исходники, статьи и согласованные исследовательские заметки вынесены в локальный архив вне репозитория. `mag_works/` — отдельно добавленные пользователем отчёты за два семестра, их сохранять. Не удалять пользовательские файлы или результаты под видом очистки без согласованного списка.
