# Анализ: действующие возможности и ограничения

Новый GUI/CLI сбора и старые аналитические скрипты находятся в одном проекте, но **пока не образуют единую команду полного анализа**. Сбор, словарная тональность и классификация по ЦУР — отдельные операции.

## Словарная тональность

Во вкладке «Анализ среза» можно выбрать Excel и один или оба словаря:

- «Словарь 1» — КартаСловСент, файл `data/kartaslovsent.csv` (разделитель `;`).
- «Словарь 2» — RuSentiLex, файл `data/rusentilex.csv` (разделитель `,`).

Новый сборщик записывает первую колонку `text` с заголовком; чтение через `pandas.read_excel()` сохраняет первую публикацию как данные. Не подавайте исходный JSONL напрямую в старую вкладку — она ожидает `.xlsx`.

Текущий словарный подход даёт базовую тональную оценку. Он не является обученной моделью интерпретации экономических событий и не решает автоматически неоднозначности вроде «цены выросли» для разных участников экономики.

Основные реализации:

| Файл | Роль и оговорки |
|---|---|
| `src/slovari_script_new.py` | Оценка и графики, используется GUI; при импорте загружает морфологию, словари и стоп-слова NLTK |
| `src/batch_setniment_analyzer.py` | Пакетная обработка иерархии файлов; перед запуском проверьте пути в коде и наличие колонки `text` |
| `src/slovari_parse_itogi.py` | Сводные таблицы по готовым файлам `_итоги.xlsx`; ожидает старое соглашение имён |

Старый агрегатор разбирает имя файла на регион, тип, год и словарь. Новый сбор использует ID сообщества (`VK_<ID>_<год>_...`), поэтому **совместимость первой текстовой колонки не означает совместимость всего старого агрегирующего конвейера**. Для него потребуется явное сопоставление ID с регионом и согласование имён/метаданных. Автоматически переименовывать или считать ID регионом нельзя.

## Классификация по ЦУР (SDG)

`src/evaluate_script.py` относит русскоязычные тексты к одной из 17 целей устойчивого развития. Это не новая модель тональности.

Для существующей реализации:

1. Используйте отдельное окружение Python 3.10 с `requirements02022026.txt` — TensorFlow 2.10.1 не рассчитан на новые версии Python.
2. Разместите внешнюю модель в `rubert_bert_RU_35data_6_epochs/` или передайте путь.
3. Из корня проекта выполните:

```bash
./myenv/bin/python src/evaluate_script.py \
  --input_folder /путь/к/Excel \
  --model_path rubert_bert_RU_35data_6_epochs/ \
  --threshold 0.9 --batch_size 24
```

`myenv` здесь означает подготовленное ML-окружение, а не универсальное имя обязательной папки. На Windows укажите соответствующий путь к `python.exe`. Полный набор параметров смотрите в коде/справке скрипта; для запуска справки уже могут потребоваться ML-зависимости.

Модель — **TensorFlow SavedModel**, а не каталог модели HuggingFace. Загрузчик пробует `load_model()` и альтернативное создание архитектуры с загрузкой весов, использует базу `DeepPavlov/rubert-base-cased`. При отсутствии локального кеша могут понадобиться сетевые загрузки. Модель и веса не устанавливаются через `requirements-gui.txt` или `requirements-cli.txt`.

## Другие скрипты

| Файл | Назначение |
|---|---|
| `src/sdg_prepare_script.py` | Разделение классифицированных таблиц по ЦУР |
| `src/sdg_economic_analysis.py` | Укрупнение ЦУР в социальную, экономическую, экологическую категории |
| `src/sdg_sentiment_cross.py` | Тональность по категориям, регионам и годам |
| `src/extract_rosstat.py`, `src/merge_and_correlate.py` | Подготовка и сопоставление статистических данных; перед запуском проверить ожидаемые файлы и пути |
| `src/experimental_sdg_normalized_analysis.py` | Экспериментальные проверки нормировок и отдельных ЦУР, не основной продуктовый сценарий |
| `src/analyse.py` | TF-IDF и Random Forest/KNN; нужны внешние `combcombcomb.xlsx` и `comb_test_1.xlsx`, которых нет в репозитории |
| `src/diag.py`, `src/razmet_script.py` | Специализированные графики и сравнения |

У нескольких старых скриптов пути заданы непосредственно в исходнике. Запуск `python script.py` без проверки этих путей не является воспроизводимым экспериментом.

## Что предстоит

Подготовлен отдельный экспериментальный PyTorch baseline оценки публикаций: A — отбор, B — четыре оценки и восемь тем. Код, подготовка Windows-ПК и замеры описаны в [руководстве обучения](rubert-training.md). Он не встроен в GUI/CLI сбора и не заменяет проверку качества машинной разметки. Групповая тестовая часть предварительного набора не является независимым человеческим эталоном. Прогнозирование и графовый анализ связей с Росстатом по-прежнему не являются готовыми функциями приложения.
