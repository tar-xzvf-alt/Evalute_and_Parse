# CLI сбора ParseVK

CLI использует те же `vk_collection.py` и `collection_workflow.py`, что и GUI. Реализован сбор публикаций: комментарии, словарный анализ, обучение и SDG-модель пока не входят в этот интерфейс команд.

## Запуск без графической среды

Из корня репозитория:

```bash
.venv-gui/bin/python -m parsevk --help
.venv-gui/bin/python -m parsevk collect --help
```

Подходит и существующий `myenv`. На сервере достаточно отдельного окружения Python 3.10+ с минимальными зависимостями:

```bash
python3 -m venv .venv-cli
.venv-cli/bin/python -m pip install -r requirements-cli.txt
.venv-cli/bin/python -m parsevk --help
```

Tk, DISPLAY, CustomTkinter, NLTK и TensorFlow не требуются. Windows: используйте `python` своего окружения вместо Linux-пути `bin/python`. Из другой рабочей директории можно запустить `python /путь/к/репозиторию/parsevk.py ...`.

## Токен и пути

Для каждого сетевого вызова приоритет такой:

1. `--token-file /путь/к/файлу`;
2. переменная окружения `VK_TOKEN`;
3. `vk_token.txt` в текущей рабочей директории.

Пустой явно указанный файл считается ошибкой; программа не подменяет его другим ключом. Секрет не принимается аргументом командной строки. Не публикуйте файлы токенов.

Все относительные пути, включая папку внутри профиля, разрешаются относительно **текущей рабочей директории**, а не местоположения профиля. Для запуска из cron/SSH рекомендуется явно задавать абсолютные пути. Папки результатов должны уже существовать; CLI не создаёт их неявно.

## Команды

Ниже используется `.venv-gui`, но графическая среда этим командам не нужна.

### Поиск → оценка → отбор

```bash
.venv-gui/bin/python -m parsevk search \
  --query "Омск новости" --limit 20 --output candidates.json

.venv-gui/bin/python -m parsevk assess \
  --input candidates.json --year 2019 --output assessed.json

.venv-gui/bin/python -m parsevk verify \
  --input assessed.json --year 2019 --output verified.json

.venv-gui/bin/python -m parsevk select \
  --input assessed.json --year 2019 --maximum 3 --minimum 100 \
  --output selected.json --save-profile omsk-profile.json
```

- `search`: M кандидатов, не более 1000; не выбирает источники автоматически.
- `assess`: оценка по границам года для всех источников входного файла.
- `verify`: полный обход года, проверенный подсчёт и массив из 12 месячных количеств.
- `select`: заново оценивает кандидатов, уточняет около порога N и потенциально проходящие источники, отмечает до K наиболее активных. Месячное покрытие не является фильтром. Правила совпадают с GUI.

Для `assess`, `verify`, `select` год можно не передавать, если он записан в профиле. Новый результат поиска не содержит года: для его первой оценки **обязательно задайте `--year`**. Это защищает от случайного запуска с неподходящим стандартным периодом.

Вход — JSON версии 1 с `settings` и `groups`: подходит профиль GUI или результат предыдущей команды. Результаты дополнительно содержат `status` и `api_calls`, а строки — `count`, `verified`, `year`, при полном подсчёте — `months`, при ошибке — `error`. `count: null` при ошибке не означает ноль публикаций.

`--save-profile` у этих четырёх команд дополнительно записывает компактный профиль для GUI без результатов измерения. Обычный JSON-результат также открывается в GUI. `select` не скачивает корпус на диск; данные проверки будут получены повторно при последующем сборе.

### Сбор выбранного набора

```bash
mkdir -p data/raw/omsk/2019
.venv-gui/bin/python -m parsevk collect \
  --profile omsk-profile.json --year 2019 --output data/raw/omsk/2019
```

Или явные положительные ID сообществ:

```bash
.venv-gui/bin/python -m parsevk collect \
  --groups 50738246,50386446 --year 2019 --output data/raw/omsk/2019 \
  --keywords "занятость,зарплата" --min-words 5
```

`collect` по профилю и `run` используют только `selected: true`. Пустой выбор — ошибка, а не повод выбирать все источники. По явным ID выбираются все перечисленные сообщества.

### Повторный запуск профиля

```bash
mkdir -p data/raw/omsk/2020
.venv-gui/bin/python -m parsevk run \
  --profile omsk-profile.json --year 2020 --output data/raw/omsk/2020
```

`run` **не запускает поиск или переподбор**, даже если в профиле сохранено `mode: Автоматически`. Для нового отбора нужна отдельная команда `select`.

`--year`, `--keywords`, `--min-words`, `--output` переопределяют параметры только текущего запуска; исходный профиль не меняется. Если `--output` не указан, используется `settings.folder` профиля.

Корпус сохраняется в Excel, исходные тексты — в JSONL, паспорт — в JSON, как в GUI (см. [vk-collection.md](vk-collection.md)). На stdout выводится JSON с путём паспорта. `--report summary.json` сохраняет этот итог в файл. Периоды — UTC, фильтр стены — `owner`.

## Автоматизация и ошибки

- `stdout` — только JSON успешной/частичной операции; `--output файл` у поиска/оценки/отбора переносит JSON в файл.
- `stderr` — прогресс и ошибки. `--quiet` убирает прогресс, но не ошибки.
- Команды не задают интерактивных вопросов и не открывают окна.
- Некорректные локальные параметры проверяются до сетевых запросов.
- При ошибках отдельных источников оценка/отбор записывают JSON со статусом `partial` и возвращают ненулевой код. Если такой результат используется для сбора, оператор должен явно принять решение о частичном наборе; сам сбор не восстанавливает исключённые источники.
- Ctrl+C возвращает 130, SIGTERM — 143. Во время экспорта паспорт помечается как отменённый, уже завершённые файлы сохраняются. Во время поиска/оценки итоговый JSON при отмене не записывается.
- JSON-результаты команд записываются через временный файл с заменой готового файла. Явно заданный существующий выходной файл заменяется; при неудавшейся записи прежний файл сохраняется. Компактные профили используют тот же механизм сохранения, что GUI.

Коды завершения:

| Код | Значение |
|---|---|
| 0 | Успех (включая пустой результат поиска) |
| 1 | Ошибка записи/данных во время выполнения |
| 2 | Некорректные аргументы, профиль, пути или отсутствие токена |
| 3 | Ошибка API/сбора, не позволившая завершить операцию |
| 4 | Оценка/отбор завершены с ошибками источников; JSON частичный |
| 130 / 143 | Отмена через Ctrl+C / SIGTERM |

Ограничения полноты VK и нестабильности offset остаются такими же, как у GUI. CLI не делает снимок стены и не обходит ограничения доступа.

## Проверки

```bash
.venv-gui/bin/python -m unittest discover -s tests -v
```

Подпроцессные тесты используют отдельный подменный клиент, не подключаются к сети, не читают настоящий токен и запускаются без DISPLAY. Они проверяют JSON, профили, общий отбор, коды завершения, частичные результаты и отмену. В рабочем CLI нет флагов подмены API или тестовых данных.
