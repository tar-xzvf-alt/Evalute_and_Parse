# Контрольный сбор перед разметкой

Цель — проверить данные и процесс, а не сразу получить обучающую выборку. Положительный статус API и непустой Excel ещё не доказывают пригодность корпуса.

## Небольшой проверяемый запуск

1. Выберите один регион, один год и не более 2–3 источников.
2. Сохраните кандидатов, результаты оценки/отбора и профиль в каталоге эксперимента внутри `data/raw/`.
3. Для первого корпуса оставьте тематические фразы пустыми: это позволяет оценить шум и не потерять новости из-за узкого словаря. Правила рекламы и тематического исключения пока не применяются автоматически.
4. Выполните полный сбор выбранных источников, сохранив паспорт.
5. Не смешивайте его с другими запусками; имена выходных файлов содержат время.

Для кандидата на обучающий период обсуждался 2019 год. Его пригодность нужно подтвердить данными, а не считать установленной заранее.

## Проверка файлов

- Паспорт имеет статус `complete`; каждый запланированный источник завершён.
- `available` в паспорте совпадает с числом строк исходного JSONL.
- `retained` совпадает с числом строк данных в Excel (без заголовка).
- Записи без непустого текста остаются в исходном JSONL, но в Excel не включаются даже при минимуме слов 0. Поэтому различие `available` и `retained` само по себе не означает потерю публикаций: сначала проверьте причины фильтрации. Текст изображений и других вложений сборщик не распознаёт.
- Уникальность проверяется парой `(group_id, post_id)`: ID поста уникален в пределах стены, а не всего VK.
- Все исходные даты попадают в UTC-интервал выбранного года.
- Первая публикация не потерялась при чтении Excel; первая строка — заголовок `text`.
- Текст в Excel соответствует исходному после заявленной очистки и ограничения длины ячейки; полная версия остаётся в JSONL.
- Месячные количества по JSONL совпадают с результатами полного подсчёта, если стена не менялась между операциями.
- Нет токенов в профиле, паспорте или журнале.

Если проверка выявила расхождения, сначала выясните причину. Не корректируйте число записей вручную, чтобы «сошлось».

Если один источник завершён, а другой остановился из-за изменения стены, весь запуск остаётся незавершённым. Проверенные файлы первого источника можно анализировать отдельно с явным указанием этого ограничения. Не объединяйте их с неподтверждёнными данными и не перезапускайте уже завершённые источники без необходимости.

Для завершения используйте тот же набор и параметры с «Продолжить…» в GUI или `--resume` в CLI. Убедитесь, что новый паспорт отмечает прежние источники как `reused: true`, указывает прежние файлы и завершает оставшиеся. Подтверждённые сдвиги стены отражаются в `recovery_count`; отсутствие сдвига в конкретном живом запуске не заменяет тестов восстановления.

## Проверка состава

На небольшой выборке прочитайте публикации, не ограничиваясь первыми строками:

- представлены ли разные месяцы;
- относятся ли события к нужному региону, а не только опубликованы местным пабликом;
- сколько рекламы, происшествий, федеральных новостей, коротких анонсов;
- есть ли экономические и социально-экономические сообщения;
- встречаются ли одинаковые тексты внутри источника и между источниками.

Удаление повторов по ID защищает выгрузку, но **не удаляет дубли одного новостного материала**. Перед разбиением на обучающую, валидационную и тестовую части потребуется группировка текстовых дублей.

## Завершение этапа

Зафиксируйте локальный отчёт с выбранными источниками, месячным покрытием, результатами сверки и обнаруженными ограничениями. Корпус и отчёт с данными не включайте в Git автоматически.

Следующий шаг — небольшой набор для согласования правил разметки. Автоматические метки, принадлежность к теме и окончательное качество обучения на этапе контрольного сбора не утверждаются.
