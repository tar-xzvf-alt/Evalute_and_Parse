# Подготовка обучения двух RuBERT-моделей

Статус: организация среды; обучение ещё не запускалось. Ручной просмотр разметки временно отложен пользователем. Это не означает утверждения предложенных исправлений или признания машинных меток эталоном.

## 1. Доступ к Windows-ПК

Подключение — через SSH в локальной сети. VPN не отключать автоматически, firewall и системные маршруты без необходимости не менять. Доступность порта и серверный баннер не доказывают право входа или идентичность ПК.

Перед первым входом сверить ED25519-отпечаток на самом ПК в PowerShell:

```powershell
ssh-keygen -lf "$env:ProgramData\ssh\ssh_host_ed25519_key.pub"
whoami
```

Со стороны ноутбука использовать имя учётной записи Windows, а не предполагать, что оно совпадает с Linux. Пароли, приватные ключи, VK/OAuth-токены в чат и отчёт не передавать. При необходимости пользователь сначала входит в собственном терминале; установка авторизованного публичного ключа требует отдельного согласования. Не использовать `StrictHostKeyChecking=no` для обхода проверки ключа.

## 2. Снять характеристики без изменения ПК

На ПК запустить скрипт из корня проекта:

```powershell
powershell.exe -NoProfile -File .\scripts\inspect_training_pc.ps1
```

Скрипт выводит JSON: Windows, CPU, RAM, свободное место, модели видеоадаптеров, GPU/VRAM и драйвер через `nvidia-smi`, установленные версии Python через launcher. Ничего не устанавливает, не меняет execution policy, не читает секреты и не запускает обучение. Если политика запрещает скрипт, не менять её вслепую: сначала определить действующую политику. При сохранении отчёта использовать локальный игнорируемый каталог, не коммитить инвентаризацию пользовательского ПК. VRAM не берётся из ограниченного поля `AdapterRAM` WMI.

Скрипт проверен запуском через SSH под Windows PowerShell 5.1. Успех локальных Linux-тестов приложения не подтверждает работу Windows/CUDA.

## 3. Отдельное окружение обучения

После проверки оборудования:

1. Выбрать совместимые Python, PyTorch/CUDA wheel, Transformers и драйвер. Точные версии пока не зафиксированы; не устанавливать случайную актуальную связку.
2. Создать отдельное Windows-окружение `.venv-rubert`. Не переносить Linux venv, не менять старое TensorFlow/SDG-окружение и не устанавливать зависимости обучения в GUI-окружение.
3. Проверить импорт PyTorch, `torch.cuda.is_available()`, имя GPU и небольшой CUDA-тензор.
4. Сохранить версии и конфигурацию. CUDA Toolkit не устанавливать автоматически: для готового PyTorch wheel обычно достаточно совместимого драйвера и поставляемого runtime.
5. Выбрать базовый русскоязычный BERT checkpoint в формате Transformers и зафиксировать его revision. Существующая TensorFlow SDG SavedModel не подходит как готовая модель этой задачи.

## 4. Две обучаемые задачи

| Модель | Вход | Выход | Предварительный объём |
|---|---|---|---|
| A: отбор | Текст + регион источника | Включить / исключить | 9675 принятых по формату машинных ответов |
| B: оценка и темы | Текст + согласованный контекст | Одна из четырёх оценок + восемь независимых тем | 3394 включённых моделью текста |

У B — одна BERT-основа и две головы, multiclass для оценки и multilabel для тем; объяснения LLM генерировать не требуется. У A не обучать ID паблика как скрытую замену содержания. Конкретное кодирование региона, длина текста и обращение с длинными публикациями пока требуют решения и проверки токенизации.

Эти числа относятся к исходным меткам. 198 локально восстановленных кандидатов и неутверждённые предложения не подмешивать автоматически. Для экспериментального baseline можно позднее явно заморозить исходный снимок с отметкой `provisional_machine_labels`, не выдавая его за проверенный финальный набор.

## 5. Порядок организации запуска

1. Доступ → инвентаризация → проверка CUDA.
2. Переносимый код и конфиг, без секретов, личных абсолютных путей и копирования всего `data/raw/`.
3. Группировка точных/близких дублей и train/validation/test-разбиение до обучения. В данный момент групповых разбиений нет.
4. Статистика классов и тем в каждой части. У mixed только 226 примеров, 179 из Саратовской области; нельзя обещать надёжность редкого класса заранее.
5. Технический smoke-test на малой выборке, явно отделённый от итогового эксперимента. Он проверяет backward/сохранение/загрузку, не качество.
6. Последовательное обучение A и B на ПК. Batch size, gradient accumulation, precision, class weights и лимит эпох выбираются после проверки VRAM и длины текстов, а не копируются из старой SDG-модели.
7. Валидация: precision/recall/F1 для отбора; macro-F1 и матрица ошибок четырёх оценок; per-topic и micro/macro-F1 для тем. Пороги и выбор checkpoint — только по validation, не по test.
8. Отдельно проверить каскад A→B: качество B на истинно включённых и ошибки полного конвейера — не одна метрика.

До окончательных исследовательских выводов вернуться к отложенной проверке меток. Метрики на машинной разметке показывают согласие с ней, не независимую семантическую точность. Полноценное обучение и перенос данных не считаются уже выполненными по факту подготовки этого плана.

## 6. Реализованный предварительный baseline v1

Код отделён от приложения сбора и не импортируется новым CLI:

- `src/rubert_dataset.py` — stdlib-подготовка неизменяемого снимка, граф близких копий и групповые разбиения;
- `src/rubert_model.py` — A с двумя классами или B с четырьмя оценками и восемью темами; безопасное сохранение/загрузка safetensors;
- `src/rubert_training.py` — GPU-only команды `benchmark` и `train`, контроль хэшей и утечки групп, валидация, выбор лучшего checkpoint;
- `scripts/run_rubert_baseline.ps1` — запуск одной задачи в foreground; default=benchmark, train требует явного выбора.

Снимок локально: `data/raw/pfo/training2019/rubert_baseline_v1_seed20261107/`, на ПК: `D:\RuBERT\project_baseline_v1\dataset`. Перенесены только код/тест и подготовленные данные по фиксированному списку, SHA-256 архива сверен после передачи. Исходные сырые публикации и секреты не копировались целиком.

Зафиксирован `DeepPavlov/rubert-base-cased` revision `4036cab694767a299f2b9e6492909664d9414229` по официальному Hugging Face API. `trust_remote_code=False`. У источника только PyTorch `.bin`; загрузку выполняет установленный PyTorch 2.7.1, локальные новые checkpoints — safetensors. Это закреплённая открытая база, не пользовательские или произвольные внешние pickle-файлы.

Предварительные части 80/10/10: A — 7739/969/967; B — 2714/341/339. Все оценки/темы присутствуют. Найденные семейства не пересекают части; 112 просмотренных случаев принудительно train-only. Две группы противоречивых машинных ответов сохранены как шум и отмечены в manifest; не исправлены без человека. Защита по шинглам не гарантирует выявления всех пересказов. Подробности — README снимка.

Вход обеих моделей: tokenizer pair `(source_region, text)`. У B сумма CE оценки и BCE-with-logits тем с равными весами; A — CE. Предварительно без class weights и без подстройки порогов: темы >=0.5. Параметры baseline: AdamW lr=2e-5, weight_decay=0.01, линейный warmup 10% и decay, FP32, gradient checkpointing, длина 256, microbatch2, accumulation8 (эффективно 16), seed20261107. Это стартовая конфигурация, не утверждение оптимальности. Количество эпох по умолчанию 3, по валидации сохраняются улучшившиеся checkpoints. B выбирается по среднему macro-F1 оценки и macro-F1 тем; A — macro-F1. Test в ходе обучения и benchmark не оценивается. Проверка каскада A→B и отдельная финальная оценка test пока не реализованы этой командой.

Пример из каталога `D:\RuBERT\project_baseline_v1` (после технического допуска; новый output для каждого запуска):

```powershell
$env:HF_HOME = 'D:\RuBERT\cache\huggingface'
$env:PYTHONUTF8 = '1'
D:\RuBERT\.venv-rubert\Scripts\python.exe -m src.rubert_training train --dataset dataset --task A --output D:\RuBERT\outputs\baseline_A_run1 --epochs 3 --max-length 512
# После окончания A — отдельная команда с --task B и новым output.
```

Команда не является запущенным фоновым заданием и не умеет автоматически продолжать прерванные optimizer-state. Не закрывать сессию во время обучения; для длительного запуска предварительно организовать отдельный отслеживаемый процесс и сохранение журналов. Никакого автоматического fallback на CPU, смены модели или повторного обучения.

## 7. Согласованный запуск первого обучения

Пользователь подтвердил commit текущих наработок, точечную очистку и затем обучение A/B по приведённой512-конфигурации. Удалять разрешено **только четыре технических файла** `roundtrip/model.safetensors` в каталогах `baseline_v1_benchmark_A`, `baseline_v1_benchmark_B`, `baseline_v1_512_benchmark_A`, `baseline_v1_512_benchmark_B` под `D:\RuBERT\outputs`. Общий объём около2,65GiB. Конфиги, tokenizer-файлы и отчёты замеров сохраняются; исходная база, сырые публикации, исходные/предлагаемые метки и разбиения не удаляются. Все новые скрипты репозитория оставлены как необходимые части воспроизводимого запуска.

Для устойчивого запуска предусмотрен `scripts/train_rubert_pair.py`: A и затемB, каждая3эпохи, max512, batch2/accumulation8, seed20261107; переданный source commit записывается в паспорт. Supervisor запускается отдельной задачей Windows Task Scheduler с S4U (без хранения пароля), без повторов и без сетевого доступа: Hugging Face offline, веса уже в локальном кеше. Конкретная одноразовая задача не добавляется в автозагрузку. Результаты в новом каталоге `D:\RuBERT\outputs`:

- `status.json` — атомарный паспорт процесса и задачи A/B;
- `A_stdout.log`, `A_stderr.log`, `B_stdout.log`, `B_stderr.log` — постоянные журналы;

SSH-ожидатель может ждать Windows event без опроса по таймеру, чтобы сообщить результат; сама задача обучения от его соединения не зависит. При разрыве связи повторно не стартовать обучение вслепую: сначала проверить существующий status и задачу. Task Scheduler ограничивает запуск8часами. При принудительном завершении/перезагрузке паспорт может остатьсяrunning — это не подтверждение продолжения. Скрипт не реализует resume optimizer-state и не оценивает test.

Точные идентификатор задачи, run-dir, commit, очистка и результаты сохраняются локально в игнорируемом паспорте запуска; указание процедуры не означает, что обучение уже завершилось. Успешный supervisor и оба `completed.json` нужны для объявления полного окончания.
